# 检索式构造（【搜】的核心操作）

> 钟澄《科研论》第三章方法。术语：搜商 / 鲸吞法 / 【搜】/ 最小单元 / 万能检索式 / 小步进 / 删除测试 / 增量更新。
> 所有检索式、括号、通配符、大小写、引号均为半角原样，不要"顺手规范化"。

---

## 1. 先想清楚：这一步值多少时间

- 检索式设置属于**搜商**，是后续一切工作的起点，**直接决定了后期工作的质量、高度和完成速度**。
- 总耗时**最多一天**；涉及频繁的推理、测试、调整（试错）。
- 但如果嫌麻烦、觉得"差不多不就行了"，导致检索式不完善，后期浪费的时间会**以年计**（毕业延期、做了很久才发现课题选错了）。
- 青年教师也常栽在这里："想申请某方面的基金，但找不到相关研究"——操作检索后发现相关研究其实特别多。

**这是本 skill 所有场景的第一句回答：先花最多一天把检索式调对，别指望后面补救。**

## 2. 概念拆分到最小单元

### 2.1 为什么要拆

作者**研究 A 却从不提及 A**。最典型的例子：作者研究的是甲基铵铅碘（methylammonium lead iodide），标题里没有 perovskite 一词，只搜 `perovskite*` 就漏了。

反过来，长词组的同义表达是**组合爆炸**（ photocatalytic hydrogen production / generation / evolution / for H2 evolution / Activity for Hydrogen Evolution …），你不可能穷尽组合；但拆成最小单元后，每个单元的同义表达是有限的。

**关键原则：只要了解拆分后最小单元的同义表达有哪些，不需要了解组合后词组的同义表达方式。**

### 2.2 拆到什么程度

- 钙钛矿光催化产氢 → 3 个单元：**光催化 / 产 / 氢**（4 个单元"光/催化/产/氢"太碎，因为搜集到的表达是 Photocatalytic、Photocatalyst，说明光和催化应合在一起）。
- 冠心病 + 外泌体 → 2 个单元（两个并列概念，之间是 AND）。
- 锂离子电池 + 三元正极 → 2 个单元。
- **拆分程度由网络搜索的反馈决定**：搜索结果中找不到新表达了就停。一般浏览 20 篇以内就了解得差不多了。

### 2.2.1 由多种材料组成的器件名是一个单元，不要拆成组成元素

"最小单元"指的是**概念**的最小单元，不是**字**的最小单元。判断依据是文献里实际出现的表达长什么样：

- `lithium ion batter*` 是作为**一整个检索词**去测的（标题 34,018 条），不是拆成 `lithium OR ion`。
- 同理：**锌镍电池 / 镍氢电池 / 镍镉电池 / 锌空气电池 / 锂硫电池**各是一个单元。把"锌镍"拆成 `zinc OR nickel`，等于把两种金属当成可互换的同义词，镍氢、镍镉、锌空气、锌离子、各种碱性电池会全部涌入——这是"结果一半不相关 + 标题看不懂"最常见的单一根因。
- 反向也一样：钙钛矿光催化产氢的"光催化"不拆成"光/催化"，因为搜集到的表达是 Photocatalytic、Photocatalyst。

**操作判据**：拿不准某个词该不该拆，先按"不拆"测一次量级，再按"拆"测一次。哪个的相关度高、哪个的量级可支撑下一步，就留哪个。

### 2.3 一次只做一类事情

一次只处理一个碎片（比如只找"产"的同义表达），不要同时想多个，否则思维混乱、容易遗漏。这是"拼图碎片思维方式"。

### 2.4 长词组先确认表述本身准不准

学生问"锂离子电池**三元正极**"，钟澄先发现表述不精准：三元是用来修饰**材料**的，正极也是修饰材料的，所以应是"三元正极**材料**"。先去搜更完整的表述，再据此搜百度百科，一步拿到化学式 Li(NiCoMn)O2。

**操作：拿到课题先问自己——这个中文表述是业内通用说法吗？去掉修饰词/换更完整的说法再搜一次，看反馈。**

## 3. 同义表达的四个渠道

| 渠道 | 网址 | 用途 |
|---|---|---|
| 百度百科 | https://baike.baidu.com | 中文病名/专名的标准英文译名 |
| 百度搜索 / bing | https://www.baidu.com / https://www.bing.com | 了解概念、拿宣传报道标题看真实英文表达 |
| CNKI 学术翻译助手 | https://dict.cnki.net/index | 找关键词同义词（附词频数量级） |
| 有道翻译 | https://fanyi.youdao.com | 确认特定中文表述的英文 |

**拿百度搜索做什么（45.pdf 原文）**：一方面简单了解专有名词的基本概念（本领域的人可略过）；另一方面了解英文表达是什么、有哪些同类表达。看的是**宣传报道标题里引用的文献标题**——那是真实作者怎么写标题的证据。

### 3.1 同义表达的取舍判据

1. **频次判据**：词条后面的数字小许多（如 coronary / disease）→ 文献中出现频次低，可排除。
2. **含义判据**：只涉及概念的部分片段（如 exocrine = "外分泌的"而非外泌体）→ 排除。
3. **首轮不引入缩写**：CHD 这类缩写第一轮先不引入，除非该行业约定俗成用缩写而非全称。
4. **单复数用通配符解决**，不必列两个词条：`coronary heart disease*`、`exosome*`、`batter*`。
5. **批判性思维**：学术词典里的结果也可能错。原文保留了一个拼写错误词条 `evoltuion` 就是为了说明——**即使从学术软件中搜来的结果也不要完全信赖和盲从**。有道翻译把"锂电池正极"译成 `Lithium battery anode`（anode 是负极），也是同一个教训：**你看到的任何信息不要盲目以为就是正确的**。

### 3.2 同义表达表（边搜边记）

拿列表形式记录，防止遗漏，直译获得的表达也列在内：

```
光催化: photocatalytic, photocatalyst
产:     production, generation, evolution
氢:     hydrogen, H2
```

## 4. 万能检索式

### 4.1 原文（57.pdf）

> 绝大部分案例都是 **A AND B** 的形式……随后每个 A 和 B 考虑它们的同义表达，最终的检索式形式类似：

```
(A1 OR A2 OR A3) AND (B1 OR B2 OR B3)
```

- A1、A2、A3 表示 A 的同义词。
- **括号表示这些同义词出现在搜索引擎界面的同一行**（中英文引擎都是这样）。
- **行内只用 OR** 连接某个检索词的同义表达；**行间（不同的搜索项之间）只用 AND**。

### 4.2 强烈建议（原文）

> 有许多同学提问说自己搜出来的结果很多或者搜不到，观察了一下他们检索式的逻辑结构非常复杂，比如在同一行间会有 AND，然后行和行同一会有 OR……**所以我强烈建议采用我说的这种简单的检索式，我自己测试了几个检索案例，全都是适合这种模式的。**

**这是铁律：一行里不要同时出现 AND 和 OR。**

### 4.3 小步进测试

> 测试的时候，我们先测试最简单的，比如：A。随后一个一个的叠加限定的检索词，比如 A 测试出结果过多后，再测试：A AND B，随后再开始逐步扩充 A 和 B 的同义表达。这也是写程序常用的一种思维模式，即不要一下子码太多代码，这样出现问题你也马上能够排查。

演进路径：`A` → `A AND B` → `A AND (A1 OR A2) AND (B1 OR B2)` → 需要时 `A AND B AND C`。

### 4.4 多组检索式

一组检索式达不成目标时，用**多组检索式**分别搜索，把不同检索式获得的文献**分别导入同一个文献库**。

> **强烈建议不同检索结果分别导入不同文献库。**

### 4.5 特例：A OR B 的混合字段限定

社会化阅读案例中核心概念在标题极少见（`social* reading` 标题 738 条），但在摘要/关键词大量出现（主题 25,124 条），所以用：

```
social* reading (标题) OR social* reading (主题)
```

→ 797 条（标题命中的 738 条 + 主题额外补充的 59 条）。

**当核心概念在标题中极少时，可以用 A(标题) OR B(主题)，而不是一味地 AND。**

## 5. 字段策略

### 5.1 阶梯

```
标题（Title）
  ↓ 结果太少（几篇~十几篇）
标题 + 摘要 + 关键词（Topic）
  ↓ 结果仍不足 / 需更全面
任意字段
```

**判据：以"结果量能否支撑下一步"为唯一标准，不以学科类型为标准。** 原文：「所以使用本书的时候一定要根据你的案例中反馈的情况灵活调整，不要生搬硬套」。

### 5.2 为什么先测标题

- 高亮部位在标题，可一目了然判断检索结果是否与目标相关；相关度低就能立刻分析原因、调整检索式。
- 标题中出现的英文表达，反过来能帮你完善同义表达表（摘要中提及的往往是替换词，用于补背景知识）。
- 标题限定的词，命中即高相关。

### 5.3 TOPIC 的含义

> 注意的是 **TOPIC，不是 TITLE**。TOPIC = 标题 + 摘要 + 关键词。

## 6. 符号规则（全部半角）

| 符号 | 含义 | 示例 |
|---|---|---|
| `*` | 0 个及以上字符 | `batter*` → battery / batteries / batter |
| `?` | 恰好 1 个字符 | — |
| `"..."` | 精确匹配（词组、顺序一致） | `"high entropy" alloy*` |
| `( )` | 分组，同一行内的同义表达 | `(A1 OR A2 OR A3)` |
| `AND` / `OR` / `NOT` | 行间 AND，行内 OR；`AND NOT` 排除 | `Li*Ni NOT Lipioni or Lithosiini` |

**原文警示**：「注意以上通配符都是半角而非全角模式。」「包括我们后期提到的检索词中输入的其他符号也都是半角格式。」

大小写：WoS / Scopus 检索词不区分大小写，`Si` = `si`。

### 6.1 什么时候不加双引号

加了双引号是严格匹配（单词顺序一致、中间不夹杂其他单词）。冠心病案例中通过百度搜索和学术词典已基本明确同义表达（不采用这些表达方式的文献比例很少），所以用双引号精确匹配。**原文：「在之后的案例中，我们还会看到有些情况是不加双引号更好。」**——当词组中间可能夹杂其他单词时（如 `photocatalytic` 与 `hydrogen` 之间有 for / Activity for 等），加双引号会漏。

## 7. 实测校验：每个候选词组回引擎测量级

**不要凭直译想当然，每个候选词组都回引擎测命中量级。**

### 7.1 量级对比实例（原文数字）

| 对比 | 结果 | 结论 |
|---|---|---|
| `lithium ion batter*`（标题） | 34,018 | 基准 |
| `lithium ion cell*`（标题） | 1,098（约 3%） | cell 表达少，但存在；要囊括就用 `batter* or cell*` |
| `lithium ion batter*` AND `ternary positive electrode`（标题） | **0** | 直译完全不可用 |
| `lithium ion batter*` AND `ternary cathode`（标题） | 23；扩展主题 384 | 也只能覆盖不到 3% 的文献 |
| `three-element` + `lithium ion battery` | 无相关记录 | three-element 不用于三元材料 |
| `ternary lithium ion battery`（百度） | 大量相关结果 | ternary 是对的 |
| `high entropy alloy*`（标题） | 8,255 | 基准 |
| `high entropy alloy*`（主题） | 82,556 | 扩展后 |

### 7.2 直译法的失败（核心教训）

学生把"光催化产氢"直译成 `photocatalytic hydrogen production` 加双引号去搜，会漏掉大量文献：

| 文献实际写法 | 与直译的差异 |
|---|---|
| `photocatalyst for H2evolution` | 用 photocatalyst 不是 photocatalytic；用 evolution 不是 production；中间还有个 for |
| `Photocatalytic hydrogen generation` | generation 不是 production |
| `Photocatalytic Hydrogen Evolution` | evolution |
| `Photocatalyst for Visible Light-Driven Hydrogen Generation` | 差异更大 |
| `Photocatalytic Activity for Hydrogen Evolution` | 中间多了 Activity for，且 H2 替代 hydrogen |
| `Photocatalytic H2Evolution` | H2 |

**如果作者研究 A 但标题没提 A，靠 A 本身搜不到。解法：把 A 极致拆成最小单元，用"散点覆盖"命中下位词。**

```
perovskite* or halide or iodide or halogen (标题) and hydrogen or H2 (标题) and evolution or production or generation (标题)
```

### 7.3 单侧命中数验证法

分别单独搜每个概念，看量级是否合理，判断是"检索词选错了"还是"这两个概念结合的研究确实少"：

- 冠心病 3 变体单独（标题）→ 55,065（说明冠心病检索词没问题）
- `exosome*` 单独（标题）→ 16,555（说明外泌体检索词没问题）
- 两者 AND → 11（标题）/ 140（主题）→ **说明外泌体和冠心病结合的研究很少**

这是开题找 idea 的机制（见 §11）。

### 7.4 删除测试

结果过多时，按顺序尝试：
1. 增加以 AND 逻辑引入的检索词；
2. 缩减一些以 OR 连接的同义表达；
3. 把已在摘要/主题搜的词**限定回标题**搜索。

结果适中就进入下一步。

## 8. 化学式与特殊形式

- 化学式可直接作为检索词：`Li(NiCoMn)O2`、`LiNi(0.6)Co(0.2)Mn(0.2)O(2)`、`LiNi(0.8)Co(0.1)Mn(0.1)O2`、`LixNi(0.5)Mn1.5O(4)(x equals to 0.96, 0.98, 1.0, 1.02 and 1.04)`。
- 通配符简写：`Li*Ni`（Li 与 Ni 之间有其他字符）。
- **排除误报**：`Li*Ni` 会命中 `Lipioni`、`Lithosiini`，用 `Li*Ni NOT Lipioni or Lithosiini`。
- 型号命名：NCM333、NCM523、NCM622、NCM811、NCA（N=Nickel、C=Cobalt、M=Manganese、A=Aluminum）。
- 注意期刊名/专辑名的全大写形式（`LITHIUM-ION BATTERIES`），不要因大小写误判。
- 若某概念有"三元/ternary"这类修饰，先百度确认（`ternary lithium ion battery` vs `three-element lithium ion battery`），再进学术引擎测。

## 9. 排噪

- `AND NOT TITLE ("Chinese population" OR "Chinese patient*")`：`chinese` 会大量命中只是描述中国人群/中国社会的文献。
- 用更精确的词组替代笼统词：`chinese` → `"Chinese medicine" OR "Chinese Herb*" OR "Chinese drug"`，命中数从 10,538 降到 7，相关度大幅提升。
- `AND NOT TITLE-ABS-KEY ("animal model")`：121,261 → 排除动物实验模型类误报。
- Scopus `LIMIT-TO ( EXACTSRCTITLE , "..." )` 限定期刊名精确匹配，是**无法进一步收紧检索词时的兜底手段**：

```
( TITLE-ABS-KEY ( personalit* ) AND TITLE-ABS-KEY ( model* ) AND TITLE-ABS-KEY ( animal* ) ) AND ( LIMIT-TO ( EXACTSRCTITLE , "animal behaviour" ) OR LIMIT-TO ( EXACTSRCTITLE , "behavioral ecology and sociobiology" ) )
```

## 10. 无法穷尽时的处置（56.pdf 三个真实病例）

### 10.1 保留最小单元，不穷尽同义表达

学生做"高分子聚合物燃料电池 + 老化"，第一部分的同义表达已有 30 种还在增长：

> 至于学生说的"第一部分自己感觉已经有 30 种表达，感觉也没法穷尽"，**我觉得这部分没有必要穷尽，反而是可以保留最小单元先去测试即可**，比如我们只保留燃料电池，那么就可以把他说的这 30 种表达全部囊括了，而并没有必要用 or 的方式连接那么多种表达去搜索。

搜索过程中会陆续获得更多同义表达，**一定会将绝大多数主流文献囊括在内**；期间可用增量更新补充。

### 10.2 删除 / 精简：保留最小单元以获取未知信息

机械设计案例："定梁龙门加工中心的结构分析"，零部件（床身、导轨、立柱、十字溜座、横梁）无法穷尽，且很多文章不提"机床"。

> **我们并不需要去搜索结构**，而是去搜索我们到底要针对什么样的龙门加工中心去做什么样的研究。

- "结构分析" → 替换为更明确的"有限元""力学"（要做有限元分析多少会涉及结构分析，文献不会刻意强调"结构"）。
- 先简单搜"龙门加工中心 + 机床"，随便浏览标题，马上知道能做哪些研究（有限元分析、力学分析就是这么发现的）。
- 限定词可从简：去掉"定梁"，放宽到"机床"。

建筑碳排放权分配案例：先尽可能去除检索词——只搜"碳排放权 + 分配"，甚至只搜"碳排放权"，看其他领域围绕它能做哪些研究、有哪些可借鉴到建筑的，同时了解"分配"有哪些表达或能否不作为检索词。结果过多再加"建筑"。碳排放权本身也可再缩（只保留"碳"），虽然会引入大量不相关结果，但可能带来碳交易等启发。

### 10.3 接受 90%，增量更新

> 一旦涉及到这种无法穷尽的场景，就说明你已经获取了足够多的可以打开你思路、帮助你形成具体研究方案的文献了，而且最主流的核心文献应该已经被囊括在内了……**有的案例也是可以做到 100% 覆盖度的，有的案例也要接受做不到 100%，那能做到 90% 以上也很不错了。**

**两个极端都不能走**：另一端是"少量相关文献就立即开始研究"——基于少量文献开展研究，未来走一年以上弯路并不稀奇。

增量更新：后期发现新的同义表达，只补增量，不会重复浏览先前看过的内容（像 APP 升级）。用跟踪服务订阅（见 library-building §6）。

## 11. 检索过程本身就在启发 idea

- **交集法**：A 领域研究的人多，B 领域正成为热点且思路可迁移 → `A AND B` 搜索，在交集中找思路。如肿瘤治疗 + 基因编辑。
- **A+B 的演化**：有人提出某系统工作原理（A），就有学者考虑能否用于哺乳动物细胞（B）→ A+B；刚开始全世界只有几篇，一旦发表便爆炸式增长，还会出现 A+B+C。
- **年份分布判断热度**：检索结果若集中在近 2 年，说明是近年才受迅速关注的领域——**很可能别人也正在开展和你非常相似的工作**，要估计能否更快发表。
- **他山之石可以攻玉**：高熵合金案例中，从结果发现已扩展到 high entropy oxide、intermetallic compounds、MAX phase、硅化物、尖晶石——高熵氧化物薄膜的制备可参考高熵合金薄膜的制备方式。
- **没创新？是文献没看全。** 社会化阅读案例把 566 条全部导入，鲸吞法很快过完，真正相关的只有几十条，但空白点自然浮现。

## 12. 检索阶段几乎不读文献

> 和常规的一边检索一边下载和阅读相关参考文献不同，我们在检索的时候，**几乎不会做任何下载文献的操作，甚至深度阅读也几乎没有**……大部分我们都不去读它的摘要，只是看了非常少量文献的标题。

少数需要读摘要时也是**跳读**：利用关键词定位，只读关键词附近的语句。且与是否具备该领域背景知识无关。

排序：默认按相关性；**钟澄倾向日期降序（Recently added）**——无倾向性地按相关性排序，更容易看出检索式针对性强不强（前十几条中有不少相关的，整体相关度就较强），也能尽快看到最新工作。

## 13. 操作清单（可直接照做）

1. 拿到课题 → 确认中文表述准不准（换更完整说法再搜一次）
2. 拆成最小单元 A、B（可能 A+B+C）
3. 四个渠道为每个单元建同义表达表（边搜边记）
4. 组万能检索式：`(A1 OR A2) AND (B1 OR B2)`，行内 OR 行间 AND，全半角
5. 先测 A → 过多则 A AND B → 再逐步扩充 A1/A2、B1/B2
6. 每个候选词组回引擎测量级，对比决定去留
7. 标题测完扩 TOPIC；仍不足再扩任意字段
8. 记录每一轮命中数（跟踪检索数量）
9. 确定后保存检索历史 / 创建跟踪服务
10. 进入 library-building.md（【聚】）
