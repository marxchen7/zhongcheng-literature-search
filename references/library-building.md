# 入库【聚】：从数据库到干净文献库

> 钟澄《科研论》第三章 58.pdf/60.pdf + 第七章 95.pdf。术语：【聚】/ 形成记录 / 提示记录 / 去重 / 跟踪服务 / 增量更新 / 钓鱼法。
> 所有选项名、按钮名、文件名后缀均为原文，不要改写。

---

## 0. 先回答一个常见疑问：为什么要导入文献库

> 文献库中文献的数量少则几百，多则几万，不可能都作为文字素材库的来源……**文献库是整个文字素材库的起点。**

检索阶段几乎不下载、不读摘要（见 search-formula §12）。把检索记录批量导入文献库，是为了后续【分】字诀能迅速选出有参考价值的文献。

**检索阶段读文献的模式**：不做任何下载操作，深度阅读为 0，摘要也不读，只看非常少量文献的标题。少数读摘要也是**跳读**——利用关键词定位，只读关键词附近的语句。这与是否具备该领域背景知识无关。

## 1. 导出：Web of Science

### 1.1 先登录账号

输入检索词之前先在右上角登录 WoS 账号（没有就先注册）。

> 一旦登录账号后，万一操作过程中途出了什么意外，诸如网页突然无法打开，不小心把页面关了，我们也可以通过帐号保存的内容，找到先前保存的列表、检索式等。

左侧菜单栏下方有**历史记录**，保存了登录后所做的一切操作：**检索式、检索时间、检索数据库、检索结果数量**。结果数量最右边三个图标：复制检索式、编辑检索式、创建跟踪服务。

### 1.2 标记结果列表（Marked List）

1. 第一条检索记录上方点 **"添加到标记结果列表"**。
2. 弹窗两个选项：默认是"本页面所有记录"；第二个是**输入记录范围**——要导出全部就选这个，输入 `1至6210`。
3. 可创建新列表（如"硅负极"）并添加。
4. 左侧文件夹图标 → Marked List → 找到该列表，确认数量。

### 1.3 导出 Endnote desktop 格式

1. 点开标记列表 → 第一条记录上方 **导出**按钮 → 选 **"Endnote Desktop"**。
2. 弹窗第二行输入记录范围，**一次不能超过 1000 条**：
   - `1至1000`、`1001至2000`、`2001至3000`、`3001至4000`、`4001至5000`、`5001至6000`、`6001至6210`
   - 共 **7 个 `.ciw` 文件**
3. **弹窗最下方选择导出的记录内容——默认只有作者、标题、来源出版物，不包含摘要。**

> **我个人强烈建议加上摘要，因为我后期文献库的处理需要结合摘要。** 一些学生看着我的文献库演示视频经常问我，为什么自己的文献没有显示摘要，也是这个原因。

4. 下方两个选项：**完整记录** / **全记录与引用的参考文献**——按需选择。想在 EndNote 里直接看到某篇文献引用的文献列表，就选含参考文献的。

## 2. 导出：Scopus

### 2.1 必须用新版

> 老版本只支持 1 次导出 2000 条，而**新版本可以一次性导出更多的文献，上限为 20,000 条**，所以我们选择新版本。

页面有"尝试新版本（Try the new version）"链接，导出记录数上有区别。

### 2.2 导出全步骤

1. 第一条记录上方点 **`All`** → 选 **`Select all`**（记录多，一页页选不现实）。
2. 旁边出现 **`Export`** → 选 **`RIS format`**。
3. 弹窗中**默认不包括摘要（Abstract）和关键字（Author keywords），把这 2 个字段选上**。
4. 其他字段按需勾选 → `Export` → 得到 `.ris` 文件。

### 2.3 双库合并

文科领域默认 Scopus + WoS 双库：**两个搜索引擎都会包含一些另一个搜索引擎中没有搜到的文献**。为确保全面，把两个引擎的结果全部导入同一个文献库（采用去重导入，或导入后重新去重）。

> **强烈建议不同检索结果分别导入不同文献库。**

## 3. 导入 EndNote

### 3.1 建库

`File -> New` → 命名，**建议名字不要太长**（案例：`SiB`、`Soc`），目录不要太深。

### 3.2 Import Option 是关键

| 来源文件 | Import Option |
|---|---|
| WoS 导出的 `.ciw`（Endnote desktop） | **ISI-CE** |
| Scopus 导出的 `.ris` | **RIS** |
| WoS 导出的文件（ch7 案例表述） | **ISI** |

原文：钟澄一开始选默认的 `Reference Manager (RIS)`，发现导入结果不对，又依次试了 `Endnote Library`、`Endnote Import`、`Refer/BibX`、`Reference Manager (RIS)`，全部不对，最终才测到 **ISI-CE**。

> **如果 ISI-CE 方式也不对的话，而且所有的选项都被我们试过了，那就还可以更换下当时检索引擎完毕后导出的文件格式，总之肯定是可以解决这个问题的。**

**Duplicates 一栏**：倾向选 `Discard Duplicates`（去重导入）——好处是同一文件误导入两次无影响，遗漏文件也容易被发现（总数量会比检索记录少过多）。

双库合并场景也可以先 `Import All`（不去重），方便检查导入是否正确，之后再统一去重。

### 3.3 对账

- 1000 条 → 实际 **996 篇**（4 篇重复）
- 7 个 ciw → **6192 篇**（6210 − 18）
- Scopus 6254 → 导入后 6252（少 2 篇）

> 有的时候确实会发现这些小的 bug……但考虑 6000 多篇中只缺少 2 篇，并不影响我们的操作（而且我们之后还会结合【搜.钓鱼法】的操作补充一些对我们而言非常关键的文献），我们可以继续往下推进。

**重复的原因**：有的没有卷期号，说明检索记录中可能同时包含了刚在线（上网）时的记录和带卷期号的记录，其实是同一篇。

## 4. 去重（重点，防误删）

### 4.1 去重规则

`Edit -> Preferences -> Duplicates`，勾选：

- **title（标题）**
- **Author（作者）**
- **Secondary Title (Journal)（期刊）**
- 勾选 **"Ignore spacing and punctuation"（忽略空格和标点符号）**

即**标题、作者、期刊同时重合（忽略空格和标点）才判重**。

### 4.2 执行去重

1. `References -> Find Duplicates`
2. 弹窗点 **Cancel**（不要直接确认删除）
3. 返回页面中**灰色色块标记**的就是候选重复文献
4. 长按拖动选中 → 往下翻核对 → 拖入左侧 `Trash`

### 4.3 主动实验：去掉 Author 勾选

去掉 Author 再查一次，会暴露两类边界情况：

**(a) 同一篇、作者格式微差 → 被规则漏判**

> 比如"The effect of image enhancement on influencer's product recommendation effectiveness..."这篇文献，对应的作者格式一条记录是 **Zhang, Y. J.** 等，另一条记录是 **Zhang, Y.** 等，这种作者格式上细微的差别，按照之前的去重规则，就会被认为是不同的 2 篇文献，其实是同一篇。

**(b) 同标题、不同作者 → 是不同文献，不能删**

> 但是继续往下翻，会发现有些题目相同的记录，作者也完全不同，表明是不同的文献（记录），如下图中的标题为 **Introduction** 的这些文献。

### 4.4 双临时分组法（防误删的关键操作）

> 这就意味着软件搜索所得的这些重复记录，**我们还要自己人工观察一下，把一些不重复的结果给挑走**……如果直接在先前默认的"Duplicate References"栏中操作，万一勾选错误或者弄到一半出错了，很容易前功尽弃，要重新做。

```
1. 软件 Find Duplicates → Cancel → 得到灰色高亮的候选重复集 D
2. 建临时组 "1"：把 D 拖入 "1"        （"1" = 全部候选）
3. 点左侧 Duplicate References → 全选 → 拖入 "2"   （"2" = 待判定副本集）
4. 全选 "1" → 再点 "2"：跨面板选，得到 "2" 中需判定的记录
5. 按 Title 排序，逐篇核对 标题+作者：
   - 确为重复 → 不动（保持高亮）
   - 非重复   → Ctrl+单击去掉高亮
6. 剩余高亮项 → 拖入 Trash
7. "1" 中残留 = 保留下来的非重复文献（本例 5 篇）
8. 删除临时组 "1"、"2"
```

### 4.5 残留声明

> 经过以上处理，我们就获得了一个**基本不含有重复文献**的文献库……说是基本不含有重复文献的原因是可能还有少量文献，他们的标题也有略微格式差异，导致也被误认为是同一篇，但这种情况不会太多，所以我们可以略过。

## 5. 形成记录（提示记录）

### 5.1 模板

```
<序号前缀>-<数据库> | <完整检索式> <检索日期(YY.M.D)>
```

### 5.2 实例

```
1-Web of Science | SiO or Si or Silicon (标题) AND "lithium ion batter*" or "li ion batter*" or "lithium batter*"
or "li batter*" or "lithium ion cell*" or "li ion cell*" or "lithium cell*" or "li cell*" (主题) | 23.1.17.

1-Scopus | social* reading (Article title, Abstract, Keywords) AND literature (Article title, Abstract, Keywords) 24.1.8

1-Scopus + Web of Science | social* reading (Article title, Abstract, Keywords) AND literature (Article title, Abstract, Keywords) 24.1.8
```

### 5.3 三段式与设计逻辑

原文：「这个记录分别提示了**数据库、检索式和检索时间**。检索时间可以用来提示你上一次检索是什么时候，标题中最前方的 **"1-"** 是为了方便我们找到这条记录，这样按标题排序，这个记录就会出现在前列」。

| 段 | 作用 |
|---|---|
| `序号-`（如 `1-`） | 按 Title 排序时置顶，方便尽快找到 |
| `数据库` | 本次检索用的引擎（新增库时改成 `Scopus + Web of Science`） |
| `检索式` | 完整照录，并标注每行用的字段（标题 / 主题 / Article title, Abstract, Keywords） |
| `日期` | 执行检索的日期，格式 `23.1.17.` / `24.1.8` |

### 5.4 操作

文献库中右键 → `新建文献（New Reference）` → 在 `Title` 输入上述内容。新增数据库时点该记录 → 下方 `Reference` → 改 `Title`。

## 6. 增量更新与跟踪服务

> 当我们觉得这组检索式不错，如果想及时得知基于这组检索式，最近又可以搜索到哪些文献……那么我们就要**点击创建跟踪服务，系统会自动将新的检索结果发送到你的邮箱**。

- 不用每次费力打开引擎、输入检索式比对有没有新增文献，只关注邮件。
- **不要一有新增记录就操作**，等新文献积攒到一定程度、或看到重要文献需要更新时再导入。
- 增量导入用 `Discard Duplicates`，不会重复浏览先前看过的内容。
- 后期发现新的同义表达，只补增量检索式，像 APP 升级一样。

**这是"无法穷尽"的标准出口**：第一轮做到 90%+ 覆盖即可，剩下的靠增量更新持续跟踪。

---

## 7. 与【搜.钓鱼法】的接口

导入对账时少的几篇、以及后期发现的关键遗漏，靠钓鱼法定向补充检索补回（见 completeness §5）。导出数量对账的容差判断：6000 多篇少 2 篇不影响操作；少得过多（如应有 1000 只有 900）要回头检查是不是漏了文件。
